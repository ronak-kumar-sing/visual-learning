## 2. Next.js 16 Breaking Changes — Read Before Writing Any Route

### 2.1 params are Promises

In Next.js 16 App Router, `params` in dynamic routes is a **Promise**, not a plain object.

```tsx
// ✅ CORRECT — Next.js 16
export default async function Page(props: PageProps<'/system-design/[group]/[topic]'>) {
  const { group, topic } = await props.params
  // ...
}

// ❌ WRONG — Next.js 14 pattern, will throw in Next.js 16
export default function Page({ params }: { params: { topic: string } }) {
  const { topic } = params  // runtime error
}
```

Same applies to `generateStaticParams` — it returns the shape, not a Promise.

### 2.2 PageProps / LayoutProps helpers

Use the globally-available `PageProps<'/route/path'>` and `LayoutProps<'/route/path'>` helpers — no import needed. They are generated by `next dev` / `next build`.

```tsx
// Page
export default async function Page(props: PageProps<'/system-design/[group]/[topic]'>) {}

// Layout
export default function Layout(props: LayoutProps<'/system-design'>) {}
```

### 2.3 Server Components by default

All files under `app/` are Server Components unless they start with `"use client"`. The step-player engine and all interactive lesson components **must** be `"use client"` because they use `useState`, `useEffect`, and `useInterval`.

### 2.4 Tailwind v4 — no tailwind.config.ts for tokens

This project uses Tailwind v4 with `@theme inline` in `globals.css`. Do **not** edit `tailwind.config.ts` for design tokens — add tokens to `globals.css` inside `@theme inline {}` or `:root {}`.

## 4. Content Registry Conventions

The canonical topic list lives in `lib/system-design/topics.ts`. **Never hard-code topic data in page files** — always import from the registry.

### 4.1 Type shape

```ts
type Difficulty = "core" | "intermediate" | "advanced";

type Topic = {
  slug: string;           // kebab-case, e.g. "cap-theorem"
  group: string;          // group slug, e.g. "performance-and-consistency"
  title: string;          // human-readable, e.g. "CAP Theorem"
  oneLiner: string;       // one sentence description for sidebar/cards
  difficulty: Difficulty;
};

type Group = {
  slug: string;
  title: string;
  accent: string;         // Tailwind color name, e.g. "amber"
  accentHex: string;      // #hex for inline SVG/canvas use
  topics: Topic[];
};
```

### 4.2 All 30 topics

```
networking-fundamentals (amber):
  client-server-architecture · ip-address · dns · proxy-reverse-proxy · latency

web-and-apis (teal):
  http-https · apis · rest-api · graphql · databases

scaling-foundations (blue):
  sql-vs-nosql · vertical-scaling · horizontal-scaling · load-balancers

database-internals (orange):
  indexing · replication · sharding · vertical-partitioning

performance-and-consistency (pink):
  caching · denormalization · cap-theorem · blob-storage

realtime-and-architecture (green):
```

### 4.3 generateStaticParams convention

```tsx

  return TOPICS.map((t) => ({ group: t.group, topic: t.slug }));
}
```

## 5. Step-Player Engine (Phase 1+)

### 5.1 useStepPlayer hook contract

```ts
// hooks/useStepPlayer.ts — "use client"
type UseStepPlayerReturn = {
  currentStep: number;
  isPlaying: boolean;
  speed: 0.5 | 1 | 2 | 4;
  play: () => void;
  pause: () => void;
  next: () => void;
  prev: () => void;
  reset: () => void;
  setSpeed: (s: 0.5 | 1 | 2 | 4) => void;
  goToStep: (n: number) => void;
};

function useStepPlayer(totalSteps: number): UseStepPlayerReturn
```

Speed → interval: `0.5x = 3000ms`, `1x = 1500ms`, `2x = 750ms`, `4x = 375ms`.
Auto-stops at `totalSteps - 1`. `currentStep` is clamped `[0, totalSteps-1]`.

### 5.2 LessonStep / Lesson data types

```ts
type LessonStep = {
  narration: string;       // one sentence, cross-fades between steps
  activeLine?: number;     // 0-indexed line in pseudocode array
  state: Record<string, string | number | boolean>;
  visualState: unknown;    // topic-specific — typed per-lesson
};

type Lesson = {
  pseudocode: string[];    // displayed verbatim in PseudocodePanel
  steps: LessonStep[];
};
```

### 5.3 LessonShell layout contract

```
┌──────────────────────────────────────────────────────┐
│ Left column (w-72)     │ Center (flex-1)              │
│  · Title               │  AnimationStage slot         │
│  · Difficulty badge    │  (SVG / framer-motion canvas)│
│  · Description         │                              │
│  · "Real World" callout│                              │
├────────────────────────┤ Right column (w-80, stacked) │
│                        │  a) PseudocodePanel          │
│                        │  b) StatePanel               │
│                        │  c) NarrationBar             │
├────────────────────────┴─────────────────────────────┤
│ Bottom: StepControls                                  │
│  [prev] [play/pause] [next]  step X / N  [speed]     │
│  ──────────────── progress bar ────────────────────   │
└──────────────────────────────────────────────────────┘
Mobile (<768px): right column stacks below AnimationStage
```

### 5.4 PseudocodePanel rules

- Lines rendered as `<pre>` with `font-mono text-sm leading-6`
- Active line: `border-l-[3px] border-[<group-accent>] bg-white/5 text-[var(--sd-text)]`
- Inactive lines: `opacity-40 border-l-[3px] border-transparent`
- Transition: `transition-all duration-200`
- `activeLine` is **0-indexed**. Always verify step data matches array indices.

### 5.5 StatePanel rules

- Renders `Record<string, string | number | boolean>` as a key/value table
- On value change: flash highlight — `bg-[<group-accent>]/20` for `600ms` then fade
- Use framer-motion `AnimatePresence` + `layout` for value transitions
- Keys formatted: `camelCase` → `Camel Case` (split on uppercase)

### 5.6 NarrationBar rules

- Single line of text, cross-fade between steps using `framer-motion` `AnimatePresence`
- Placed at bottom of right column, above StepControls
- Style: `text-sm text-[var(--sd-text-muted)] italic`

### 5.7 StepControls rules

- Scrubbable progress bar: click anywhere → `goToStep(Math.floor(clickX / width * totalSteps))`
- Speed selector: segmented `[0.5x | 1x | 2x | 4x]` pill buttons
- Step counter: `step {currentStep + 1} / {totalSteps}` in `font-mono text-xs`
- Keyboard shortcuts (Phase 11): `Space` = play/pause, `←/→` = prev/next

## 6. Animation Conventions

### 6.1 framer-motion usage patterns

```tsx
// Arrow / request token moving between nodes
<motion.div
  animate={{ x: targetX, y: targetY }}
  transition={{ duration: 0.6, ease: [0.4, 0, 0.2, 1] }}
/>

// Node pulse (server "processing")
<motion.div
  animate={{ scale: [1, 1.05, 1], opacity: [1, 0.8, 1] }}
  transition={{ duration: 0.8, repeat: 2 }}
/>

// Cross-fade narration
<AnimatePresence mode="wait">
  <motion.p key={currentStep}
    initial={{ opacity: 0, y: 4 }}
    animate={{ opacity: 1, y: 0 }}
    exit={{ opacity: 0, y: -4 }}
    transition={{ duration: 0.25 }}
  />
</AnimatePresence>
```

### 6.2 Timing constraints

| Duration | Use |
|----------|-----|
| 200–300ms | State panel flash, narration cross-fade, pseudocode highlight |
| 500–700ms | Request token travel between adjacent nodes |
| 800ms–1s  | Multi-hop sequences, server pulse |
| Never > 1.5s | Any single animation (feels sluggish at 1x speed) |

### 6.3 Reduced motion

Always wrap framer-motion animations with `useReducedMotion()`:
```tsx
const prefersReduced = useReducedMotion();
const transition = prefersReduced ? { duration: 0 } : { duration: 0.6, ease: ... };
```

## 7. Lesson-Building Checklist

When adding or editing a lesson, verify all of these:

- [ ] `LessonStep.activeLine` values are **0-indexed** and within `lesson.pseudocode.length - 1`
- [ ] Every step has a non-empty `narration` string
- [ ] `visualState` shape is consistent across all steps (undefined fields → use `null`, not omit)
- [ ] The lesson component is marked `"use client"`
- [ ] `generateStaticParams` in topic page returns `{ group, topic }` pairs
- [ ] Group accent color is applied via `accentHex` from the registry (never hard-coded)
- [ ] Framer-motion animations respect `useReducedMotion`
- [ ] Mobile: `AnimationStage` has `min-h-[280px]` and reflows below description on `<768px`
- [ ] State panel keys are camelCase strings (auto-formatted to `Title Case` in the component)
- [ ] Pseudocode array lines should read as plain English pseudo-steps, not real code (unless the lesson is genuinely about code)

## 9. Do's and Don'ts

### Do
- Import topic metadata exclusively from `lib/system-design/topics.ts`
- Use `await props.params` in every dynamic route page (Next.js 16)
- Mark all interactive lesson components with `"use client"`
- Keep `LessonShell`, `useStepPlayer`, `PseudocodePanel`, `StatePanel`, `NarrationBar`, `StepControls` API-stable — lesson pages depend on them
- Use group `accentHex` from registry for inline SVG strokes and fills
- **Infographic Layout Fidelity**: When an architectural diagram/infographic is provided, the visual stage must replicate the exact structure, layout, and visual flow of the infographic (e.g. stacked panels for Reverse Proxy, Gateway Proxy, and Load Balancer, each with left requester nodes, vertical feature stacks with dashed connectors, central proxy/gateway node, and right target server pools).
- **Vertical Feature Stacks & Dashed Connectors**: Intermediary nodes (Reverse Proxy, API Gateway, Load Balancer) must render their core capabilities as stacked feature pills with dashed line connections leading to the target node.
- **Center Canvas Visual Isolation**: The center stage (`visual` prop) MUST contain the complete, high-fidelity visual diagram representation with clean nodes, connecting directional arrows ($\rightarrow$), dashed lines, and proper icons.
- **Balanced Canvas & Card Heights**: Ensure card padding, container bounds, and font sizes are tuned so text and diagrams fill the canvas comfortably without excessive white space or cramped text lines.
- **Sidebars for Information**: Use the Left Sidebar for high-level summaries, definition tabs, and interview prep Q&A.
- **Component Hover/Click Info Tooltips**: Every visual component/node must show rich information tooltips or popover details when clicked or hovered.
- **Definition & System Design Interview Prep**: The left sidebar in `LessonShell` must feature:
  1. **Formal Definition**: Clear architectural definition of the concept.
  2. **Interview Prep & Trade-offs**: Real system design interview questions, architectural trade-offs, and common pitfalls.
- **DaisyUI Component Library**: DaisyUI components (e.g. badges, tooltips, progress, toggle, join, range, tabs, collapse) can be used for UI widgets. Reference: `https://daisyui.com/components/`
- **Pseudocode & Panel UI Rules**: Pseudocode lines must be completely visible without line clipping or browser scrollbars (`[scrollbar-width:none]`). The right/left panels in `LessonShell` must support draggable/resizable widths so users can expand or contract the sidebars as needed.
- Test each new lesson at 1x, 2x, and 4x speed before committing

### Don't
- Don't put lesson step data inside `page.tsx` — keep it in `lib/system-design/lessons/<group>/<topic>.ts`
- Don't hard-code group accent colors — always reference the registry
- Don't use `params.topic` directly without `await` (Next.js 16 runtime error)
- Don't add `framer-motion` animations with `duration > 1.5s` (feels slow at 1x speed)
- Don't import Supabase client in Server Components — wait for Phase 10 wiring
- Don't modify `LessonShell`'s layout API while lesson content phases are in progress — coordinate changes
- Don't add atmospheric gradients to the lesson shell — the dark canvas is the design
